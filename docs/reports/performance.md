# Performance report

Measured with `bench/run.sh` on Linux x86_64 (AMD Ryzen 5 7600X 6-Core Processor, 12 threads), release build, 2026-11-21.

Workload (generated by `bench/gen_collection.py`): 1,001 requests in 50 folders, 5 environments × 100 variables, 20 collection variables, 10,000 history entries, and a request that downloads a ~10 MB JSON document from the local echo server. The app runs in a 120×40 pseudo-terminal (`script(1)`).

| Measurement | Mean | p99 | Max | Target | Result |
|---|---|---|---|---|---|
| Cold start → first frame (in-process, 20 runs) | 3.0 ms | 3.8 ms | 3.8 ms | ≤ 100 ms | PASS |
| Cold start, end to end through a pty wrapper (hyperfine, 20 runs; the wrapper alone takes 20.9 ms) | 21.0 ms | 21.4 ms | 21.4 ms | ≤ 100 ms | PASS |
| Max RSS, idle with the 1,000-request collection | 12.4 MB | | | ≤ 30 MB | PASS |
| Max RSS, showing a 10 MB JSON response | 47.8 MB | | | ≤ 120 MB | PASS |
| Frame render during 60 s scroll/type (1355 frames) | 0.18 ms | 0.59 ms | 2.26 ms | p99 ≤ 16 ms | PASS |
| Longest event / async-message handling on the UI thread (1353) | 0.01 ms | 0.04 ms | 0.53 ms | ≤ 50 ms | PASS |

How each number is measured:

* **Cold start → first frame**: `sendito <collection> --exit-after-first-frame` prints the time from the start of `main` to the first frame written to the terminal (collection scan, config, session restore, first render and flush). 20 runs. The second row is the whole process measured from outside by hyperfine (20 runs, 3 warm-up), including the `script` wrapper that provides the terminal; the wrapper alone takes about as long, so the app's share is a few milliseconds.
* **RSS**: maximum resident set size of the process from `wait4()` rusage (`/usr/bin/time -v` on Linux, `/usr/bin/time -l` on macOS; `bench/maxrss.py` reads the same value when GNU time is not installed). *Idle*: open the collection and wait 3 s. *10 MB response*: send the request, wait for the body, page through it, switch raw/pretty views.
* **Frame render**: time spent in each `terminal.draw` (layout, widgets, diff and write) during a 60 s scripted session (`bench/scripts/frames-60s.txt`) that scrolls the 10 MB response and types in the URL field; one sample per frame.
* **UI thread handling**: time spent handling each input event and each message from background tasks during the same session, including the arrival of the 10 MB response (the body is parsed and indexed off the UI thread). No input waited more than the maximum shown.

Stripped release binary (`target/release/sendito`, Linux x86_64): 11156928 bytes (10.6 MB); target ≤ 20 MB. macOS arm64 sizes are reported by the release workflow.
